# OpenASO fork review before 0.4.6

Reviewed 26 October 2026 against baseline `d21d334`. This records feature research, not an import of fork code. The gaps below describe that baseline. The approved follow-up implements competition evidence in audits, scoped MCP untracking, and a Stop control; tags, market comparisons, and other proposals remain future work.

## Coverage and method

GitHub lists **29 forks**. Their published branch lists contain **91 branches**; all were compared with upstream `main` after merging PRs #87 and #88. Eight forks contain commits outside that upstream history. Every fork reports zero child forks. The remaining 21 forks have no unique commits in the inspected branches. These counts describe published branches, not private or deleted work. [Fork inventory API](https://api.github.com/repos/hubab1/OpenASO/forks?per_page=100), [upstream fork network](https://github.com/hubab1/OpenASO/forks).

Ahead/behind counts alone overstate useful additions: several forks retain old versions or differently integrated commits for capabilities already present in OpenASO. Review current behavior and individual changes rather than merging a fork wholesale. Raw branch/commit/file inventories are saved locally under `/tmp/openaso-fork-research-20261026`; they are not part of this note.

## Suggested scope

For a focused pre-release increment, prioritize **competition evidence in keyword audits**, **safe MCP untracking**, and **a Stop control for manual refreshes**. Tags and the cross-country matrix are valuable next steps but involve more persistent/UI integration. Investigate the headless launch issue as a separate release-quality check.

For ASC-specific opportunities and live API qualifications, see [ASC CLI research](asc-cli-opportunities-2026-10-26.md). Phrase discovery is an additional candidate source, not a replacement popularity API or evidence that floor scores disappear.

No fork code has been copied or merged during this review. Any future port should retain the relevant license notices and credit the original contributor, and must be adapted to current storage and concurrency boundaries.
